# 代码签名与升级验签策略（LIVE直播源）

## 1. 两件不同的事，别混

| | 是什么 | 本项目现状 |
|---|---|---|
| **Windows 代码签名**（Authenticode） | 给 exe 签证书，减少"未知发布者"与杀软拦截 | **没有做**（个人项目，证书需付费，见下方说明） |
| **升级源验签**（Ed25519） | 确认 `version.json` 与下载到的 exe 没被替换 | **已做**，客户端内置公钥验签 |

**为什么必须做第 2 件**：升级源是一个 https 地址，如果地址被劫持/仓库被改，攻击者可以让所有客户端下载任意 exe。验签把这条路堵死：签名用私钥生成，客户端只有公钥，改一个字节就验不过。

## 2. 升级验签怎么工作

发布侧（维护者本机）：

```
1. 打包出新版 exe，算出 sha256 与字节数
2. 写 version.json：{version, exe:{url, sha256, size}, notes, ts}
3. 用私钥签 version.json 的原始字节 → version.json.sig（hex）
4. 把 version.json、version.json.sig、exe 一起发布
```

客户端侧：

```
1. GET version.json + version.json.sig
2. 用内置公钥验签 → 不过 = 直接拒绝(除非用户在设置里手动关掉"必须验签"，不推荐)
3. 版本号比当前新才继续
4. 下载 exe，校验 sha256 与字节数
5. 全部对上才提示替换
```

内置公钥（客户端 `LIVE直播源.py` 里的 `UPDATE_PUBKEY_HEX`）：

```
a264516f96cffd7f79c9013fac0e480a8a6469ef5e8d1def71b6ec8df286619a
```

## 3. 私钥怎么保管

- 私钥**只在本机**：`%HARNESS_SECRETS%\raw\live-iptv-ed25519.key`（32 字节原始私钥，不入仓库、不入发行包、不进日志）。
- 发布脚本通过环境变量 `LIVE_ED25519_KEY`（指向私钥文件）读取；**没有设置就拒绝发布**，不会悄悄发出未签名的版本。
- 私钥**离线备份一份**（与另两个项目的私钥分开存放），丢失后只能换钥匙并发布一个"过渡版本"通知旧客户端信任新公钥。
- 私钥产生的 `.sig` 是公开的，可以随便传播。

## 4. 能力边界（如实写清）

验签能防：
- 升级源被篡改、CDN/仓库被替换成别人的 exe；
- 中间人替换下载内容；
- 错误打包（sha256/字节数对不上会被拒）。

验签**防不了**：
- 维护者本机被入侵（攻击者拿到私钥就能签任意包）；
- 程序自身逻辑漏洞。

## 5. 为什么不买代码签名证书

- Authenticode 证书年费数百到上千元，个人项目负担不起；
- 本项目单文件 PyInstaller 包容易被启发式误报，源码完全公开、可自行编译核对，这是当前的替代方案；
- 若要企业分发或上架商店，再补证书与 EV 签名流程。
