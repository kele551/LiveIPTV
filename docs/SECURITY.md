# 安全策略（LIVE直播源）

## 报告安全问题

请**不要**在公开 Issue 里贴可用细节（例如能让别人直接利用的复现步骤）。优先用 GitHub 的私密漏洞报告：
https://github.com/kele551/LiveIPTV/security/advisories/new

如果打不开，就开一个 Issue 只写"安全问题，请给我一个联系方式"，我会私信你。

## 本程序的安全模型（说明白了才好判断风险）

1. **只访问外部列表与流地址**：抓取你启用的 m3u 列表；测连通性/拉流时读取少量字节。除此之外不发起任何出站连接（不埋点、不上报）。
2. **不监听公网**：控制台是 `127.0.0.1` 上的本地 HTTP 服务（默认 8899，被占则顺延），只给本机浏览器用；不提供任何远程访问能力。
3. **本地文件写入范围**：数据目录 `%APPDATA%\LIVE直播源`（或 `LIVE_DATA` 指定的目录）与你自己选的导出目录；只写 `config.json`、`channels.json`、`logos.json`、`bad_urls.json`、`hosts.json`、日志、导出的 m3u，以及升级时下载的新版 exe。
4. **升级必须验签**：内置 Ed25519 公钥，`version.json` 签名不对就拒绝升级；下载后再校验 `sha256` + 字节数。
5. **不改系统设置**：不碰 hosts / DNS / 系统代理；「计划任务」「开机自启」只在用户主动勾选时由 Windows 任务计划程序登记，可随时在设置里取消。
6. **外部输入全程当作不可信数据**：列表内容只做文本解析（名称、地址、台标 URL），不执行、不 eval；地址只按 http/https 处理，URL 拼接走 `urllib`，不拼进 shell 命令。

## 已知的限制

- 列表里可能夹带失效或被劫持的地址；程序会把"返回网页"的判为失效并记入本地黑名单，但**无法鉴别流的内容**（那是播放器的事）。
- 单文件 PyInstaller 包可能被杀软启发式误报；源码公开，可自行编译核对。
- 私钥只在作者本机，签名能防"升级源被篡改"，**防不了**"作者机器本身被入侵"。
